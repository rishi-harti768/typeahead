Typeahead System Series — Lesson 0004

Consistent Hashing & Distributed Cache

Targeting: System Design Interview Success • Duration: 15 mins

In a large-scale typeahead system, a single caching server cannot hold all prefix-to-suggestion lists, nor can it handle the millions of read queries per second. We must scale horizontally by distributing our cache data across a cluster of servers.

The immediate question is: How do we route prefix keys to cache servers?

If we use standard modulo hashing: 

ServerIndex = Hash(Key) % N

Where $N$ is the number of servers.

The "Rehash Storm" Disaster: This formula works fine until $N$ changes. If a cache server crashes or we add a new server to handle peak traffic, $N$ changes. Suddenly, nearly 100% of all keys map to completely different servers. This triggers a massive, system-wide cache miss storm, driving all traffic to your fallback database and crashing your entire service.

Modulo Failure: If $N$ changes from 9 to 10, keys that hashed to Server 4 might now hash to Server 5. Over 90% of your cache lookups will instantly miss!

The Solution: Consistent Hashing

Consistent Hashing is a routing algorithm where only a fraction of keys ($K/N$) need to be remapped when the server pool size changes.

Here is how it works:

  1. We define a logical **Hash Ring** (representing hash range, e.g., 0 to $2^{32}-1$).
  2. We hash and map our **Cache Servers** onto various positions on this circular ring.
  3. We hash and map our **Prefix Keys** onto the same ring.
  4. To locate the server for a key, we start at the key's position on the ring and move **clockwise** until we encounter the first cache server. That server owns the key.

Why it scales: When you add a new server, it only splits the keys of its immediate counter-clockwise neighbor. All other servers' keys remain untouched, completely preventing cache miss storms!

Virtual Nodes: In practice, physical servers might hash to positions close to each other, creating uneven "hotspots". To fix this, we map multiple *virtual nodes* (e.g., Node-A#1, Node-A#2) per physical node across the ring to balance the key distribution.
